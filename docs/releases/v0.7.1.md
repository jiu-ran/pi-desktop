# Pi Desktop v0.7.1

内容与 v0.7.0 相同（v0.7.0 的发布流水线卡在冒烟脚本自身的时序上，没有产出安装包），另外把那段脚本改成轮询，不再赌渲染时序。

## 不再内置 Pi

会话直接跑你在本机装好的 `pi`：从 PATH 或「设置 → Pi CLI」的自定义路径解析出 `dist/cli.js`，找不到就提示安装。RPC 客户端、设置读写、软件包与资源发现、SKILL.md 解析全部由本项目自己实现，安装包里不再有 Pi 的副本 —— 连带传递依赖一共少了约 35 MB。`pi update` 之后桌面端当场就是新版本。

启动进程用 `process.execPath` + `ELECTRON_RUN_AS_NODE`，所以不再要求 `node` 在 PATH 里；扩展的安装 / 卸载 / 更新走本机 `pi install | remove | update`，失败时把输出反馈到界面。

**前置条件**：本机需要有能运行的 `pi`。没装时应用能正常打开，但不会启动会话。

自己实现后与 Pi 的差异见 `docs/pi-compatibility.md` 的「自己实现部分的已知差异」：`pi config` 那种 TUI 级逐项开关没有复刻、资源按扩展名收集、项目祖先目录的 `.agents/skills` 只在面板展示不参与合并。

## 输入框历史

- 发过的内容留在本地（最多 50 条，连续重复只留一条）；
- 输入框里 `↑` / `↓` 翻阅，翻过最新一条会还原刚写了一半的草稿；
- 只在没有选中文字且光标在首行 / 末行时接管，多行编辑时上下键仍然移动光标。

## 修复

- **「有新版本」跳到错误页面**：徽标原来写死 `environment`（环境与快捷键）。现在按来源跳：桌面应用 → Pi Desktop 页，Pi CLI → Pi CLI 页。
- **`update --all` 提示吞掉「扩展已更新」**：现在说「Pi 本体已是最新（x）；扩展包已按 update --all 检查」；设置页「上次更新结果」把输出改成可展开的几行。
- **RPC 4 个方法没接线**（自动压缩 / 自动重试 / 引导模式 / 追问模式），用了就是 `is not a function`。
- **压缩上下文被误判成失败**：超时判定改成认标记，大会话会改为等待 `compaction_end`。
- **git 来源的扩展显示「未安装」**：`git@host:owner/repo`、带端口的 `ssh://`、`owner/repo@ref` 的安装目录都算对了。
- **技能面板的「临时」筛选**已删（Pi SDK 内部作用域，桌面端产不出来）。

## 已知限制

- macOS 安装包未签名 / 未公证，首次打开需要在「系统设置 → 隐私与安全性」放行；Windows 未做代码签名，SmartScreen 可能提示未知发布者。
- Linux 的 `AppImage` 需要 `libfuse2`；没有 FUSE 的环境请用 `tar.gz`。
- 终端依赖本机已装的 CLI 与 shell，应用不会代为安装、登录或配置。
- 文本文件读取 / 保存上限 20 MB，超过 2 MB 以只读大文件模式打开。
- 「从 Git 克隆」不会代为处理凭据：需要登录的仓库请先配好凭据助手或 SSH key。

## 校验

发布产物附 `SHA256SUMS.txt`，覆盖三个平台的全部安装包。
