# Pi Desktop v0.2.6

这一版聚焦「卡死」：先把现场看清楚——界面卡死时现在会自动留下 V8 调用栈；同时把运行日志搬到程序旁边，卡在「启动中」也不会再无限停留。

## 改进

- **界面卡死会自己留下调用栈**：主进程每 5 秒 ping 一次渲染进程，连续 15 秒没有回应就判定卡死，然后暂停 V8 并把调用栈写进日志（`app.log`，带文件名、行号、列号，最多 24 层）。以前只能看到「卡住一小时、日志里什么都没有」。
  - 关键细节：调试器必须在**窗口创建时**就挂好。卡死之后再 attach，`attach` / `Debugger.enable` 本身也要排队等渲染进程回应，永远回不来；提前挂好，卡死时只剩一个 `Debugger.pause` —— 它走 V8 中断，能在同步死循环里停下来。每条调试命令都带超时，抓不到也会留下原因。
  - 开发版默认不挂（会挡住 DevTools），需要时设 `PI_DESKTOP_TRACE_HANG=1`。
- **卡在「启动中」不会无限停留**：工作区启动 30 秒未就绪记一条日志，90 秒仍未就绪就重置为可重试的错误，点一下项目即可重新启动。
- **补充卡死相关日志**：渲染进程启动成功标记（`界面已就绪`，用来区分「渲染进程没起来」和「起来之后卡住」）、`render-process-gone` 的退出原因、渲染侧心跳停摆（定时器间隔超过 3 秒即记录，恢复后补一条带开始时间的记录）。

## 变更

- **运行日志改到安装目录下的 `logs/`**：跟程序放在一起，方便直接找到、也方便打包发给别人，不再散落到各个项目里，也不再需要往项目的 `.git/info/exclude` 追加忽略项。

  ```text
  D:\dev\tool\Pi Desktop\logs\     ← 打包版：exe 所在目录
  ├─ app.log        启动/退出、IPC 失败与慢调用、卡死抓到的调用栈
  ├─ renderer.log   前端 warn/error、Vue 运行时错误
  ├─ pi.log         Pi worker 启动、切会话、压缩
  └─ perf.log       慢 IPC、主进程阻塞、渲染侧长任务
  ```

  - 开发版落在仓库根目录 `logs/`（已加入 `.gitignore`），行为与打包版一致。
  - 安装目录不可写时（整机安装到 `Program Files`、非管理员运行）自动回落到 `%APPDATA%\Pi Desktop\logs`；启动时用「建目录 + 写探针文件再删掉」探测一次。
  - 目录在启动时固定，不再跟着当前项目切换，所以同一个 `app.log` 里能看到切项目前后的完整过程。设置 → 运行日志显示实际生效的目录。
  - 上限不变：单文件 8MB 轮转、总量 100MB、按时间删最旧、写入前脱敏。

## 修复

- **跨项目点会话会报「只能删除该项目自己的会话文件」**：切换会话复用了删除操作的守卫文案，而它真正想说的是「这个会话属于另一个项目」。现在会说明属于哪个项目，并提示到对应项目里打开。

## 技术细节

- `electron/main.ts`：`startRendererWatchdog()`（5 秒 ping / 15 秒判定 / 60 秒内最多抓一次）、`armRendererDebugger()`（窗口创建时 attach + enable）、`dumpRendererStack()`（带超时的 `Debugger.pause` → 读 `callFrames` → 写日志 → resume，调试器保持挂载供下次使用）、`resolveLogDir()` + `activateLogs()`。
- `electron/logger.ts`：`useProjectLogs` → `useAppLogs`，新增 `isWritableDir()`。
- `packages/ui/src/shared/long-task.ts`：新增 `shouldReportLag()` / `installLagWatchdog()`。
- `packages/ui/src/kernel/workbench.ts`：`open()` 增加启动看门狗（30 秒 / 90 秒两级），新增 `logUi()` 把界面侧事件写给主进程。
- `scripts/checks/_hang-probe.mjs`：反向验证探针——注入 90 秒同步死循环，断言日志里出现「15 秒没有响应 ping」与带 `#0` 的调用栈。

## 校验

- ✅ 反向验证：`_hang-probe.mjs` 注入同步死循环后，日志如期出现
  `渲染进程 15 秒没有响应 ping（界面卡死），抓取调用栈` 与
  `渲染进程卡在（ping 15s 无响应）：#0 …`（PASS）
- ✅ `logger.check`：固定日志目录、启动早期日志补写、切换目录刷盘、可写性探测（用「文件当目录」模拟不可写）
- ✅ `npm run check` 全绿；Electron 冒烟 10 项 PASS，其中日志一项改为按 `logsInfo()` 的真实目录校验落盘，并断言日志**不在**项目目录里
- ✅ 现场取证：两个卡死实例表现不同——一个渲染进程占满一个核（同步死循环），另一个 CPU 空闲、窗口正常应答 Windows 消息（在等一个永远不回来的结果）。这一版先把两种情况都能留下证据

## 已知限制

- 调用栈只有在主进程判定「卡死」时抓取；如果界面只是慢（例如 5 秒一次的卡顿），只会记一条停摆日志，不抓栈。
- 日志目录跟随程序，卸载安装目录会一并删除 `logs/`；需要长期保留时请先复制出来。
