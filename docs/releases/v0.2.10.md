# Pi Desktop v0.2.10

按日志核查了一遍页面卡死：**日志里的卡顿全部发生在 v0.2.7，已被 v0.2.8 修掉**；这一版把「主进程被谁占住」这件事也记进日志，并把跨项目会话扫描改成让出事件循环。

## 日志核查结论

安装版日志（`<安装目录>/logs`，v0.2.7，启动于 08:17Z）：

```text
09:02:31 [WARN] 界面卡顿 55002ms（起于 09:01:36）
09:03:31 [WARN] 界面卡顿 59002ms（起于 09:02:32）
09:04:31 [WARN] 界面卡顿 59000ms（起于 09:03:32）
09:05:31 [WARN] 界面卡顿 59000ms（起于 09:04:32）
09:05:47 [WARN] 界面卡顿 15404ms（起于 09:05:32）
```

- 这是 v0.2.7 里「提示浮层回调自激」的表现（每次卡 ~59 秒，循环往复）；**v0.2.8（09:40Z 发布）已修**，此后日志里没有再出现同类记录。
- 开发侧「自动抓栈」抓到的两条（08:54、08:55）也是同一问题，栈落在 `restoreTitle ← restoreActive ← scheduleShow ← 全局 title 回调`，正是 v0.2.8 修掉的那条链。
- 另有两处**主进程阻塞** 1182ms / 1750ms，之前只记了时长、看不出被谁占住。

## 改进

- **卡顿日志带上「当时在做什么」**：所有 IPC 执行期间都会标记通道名，主进程阻塞时直接写成 `主进程阻塞 1750ms（pi:git-overview）`，不用再猜。
- **跨项目会话扫描让出事件循环**：`@` 引用其它项目对话时会解析每个候选会话（读头、找名称、解析 JSON，都是同步的），以前一口气连做几十个会让主线程连续阻塞；现在每 3 个让出一次，单次阻塞大幅缩短。

## 校验

- ✅ 实测 `listCrossProjectSessions(40)`：全程可被 10ms 级定时器打断（让出生效）
- ✅ 卡顿日志归属：`withActivity` 包裹的 IPC 在阻塞时能带出通道名
- ✅ `npm run check` 全绿；Electron 冒烟 PASS
- ✅ 冒烟前后 `日志里「渲染进程卡在」计数不变（2 条，均为修复前 08:54/08:55）`

## 说明

日志里那些卡顿都发生在 v0.2.7。装到 v0.2.8 / v0.2.10 之后如果还卡，`<安装目录>/logs/app.log` 会直接给出：
一是「渲染进程卡在（…）」带文件行号的调用栈，二是「主进程阻塞 Xms（哪个 IPC）」。
