# Pi Desktop v0.7.0

这一版最大的一件事：**桌面端不再内置 Pi**。安装包里没有 Pi 的副本了，会话直接跑你在本机装好的 `pi` —— `pi update` 之后桌面端当场就是新版本，安装包也小了一大截。另外输入框支持 `↑` / `↓` 翻之前发过的内容，标题栏的「有新版本」终于跳到正确的更新页，`update --all` 的提示也不再吞掉「扩展已更新」。

## 不再内置 Pi

之前桌面端把 `@earendil-works/pi-coding-agent`（25 MB，连带传递依赖约 35 MB）装进应用，会话跑的是打包进去的那份 —— 于是你在终端里 `pi update` 升级到 1.4.0，桌面端会话还在跑 1.2.0。现在：

- 会话的运行时来自**本机的 `pi`**：从 PATH 或「设置 → Pi CLI」的自定义路径解析出 `dist/cli.js`，找不到就提示安装（欢迎页本来就有这条引导）；
- RPC 客户端、设置读写、软件包与资源发现、SKILL.md 解析全部由本项目自己实现（`electron/pi-rpc.ts` / `pi-resources.ts` / `pi-entry.ts`），不再导入 Pi 的 npm 包；
- 启动进程用 `process.execPath` + `ELECTRON_RUN_AS_NODE`，所以不再要求 `node` 在 PATH 里；
- 安装 / 卸载 / 更新扩展走本机 `pi install | remove | update`，失败时把 `pi` 的输出反馈到界面。

**前置条件**：本机需要有能运行的 `pi`（`npm install -g @earendil-works/pi-coding-agent`）。没装时应用能正常打开，但不会启动会话。

自己实现后与 Pi 的差异记在 `docs/pi-compatibility.md` 的「已知差异」一节，主要是：`pi config` 那种 TUI 级逐项启用/停用没有复刻；资源按扩展名收集；项目祖先目录的 `.agents/skills` 只在技能面板展示、不参与合并。

## 输入框历史

- 发过的内容会留在本地（最多 50 条，连续重复只留一条）；
- 在输入框里按 `↑` / `↓` 翻阅，**翻过最新一条会还原你刚写了一半的草稿**；
- 只在「没有选中文字」且光标在首行（`↑`）/ 末行（`↓`）时接管 —— 多行编辑时上下键仍然是移动光标；输入法组合中不介入。

## 修复

- **点「有新版本」跳到错误的页面**：标题栏那个徽标一直写死 `openSettingsModal('environment')`，点开是「设置 → 系统 → 环境与快捷键」，跟更新毫无关系。现在按来源跳：桌面应用 → Pi Desktop 页；只有 Pi CLI → Pi CLI 页。
- **`update --all` 的提示吞掉「扩展已更新」**：`from === to` 只说明 Pi 本体没变，扩展可能刚更新过，原来却只说「无需更新」。现在提示「Pi 本体已是最新（x）；扩展包已按 update --all 检查」，设置页的「上次更新结果」也把输出从悬停提示改成可展开的几行。
- **主进程自己实现的 RPC 有 4 个方法没接线**：`setAutoCompaction` / `setAutoRetry` / `setSteeringMode` / `setFollowUpMode` 在类型白名单里但没有实现，用户一关自动压缩就是 `is not a function`。
- **压缩上下文被误判成失败**：超时判定原来匹配上游的英文文案，换成自己的客户端后永远匹配不上，大会话压缩会直接报错而不是改为等待 `compaction_end`。
- **git 来源的扩展显示「未安装」**：安装目录解析没有处理 scp 形式（`git@host:owner/repo`）、带端口的 `ssh://`、以及 `owner/repo@ref` 这种固定分支，路径算错就找不到包。
- **技能面板的「临时」筛选**：那是 Pi SDK 内部临时安装的作用域，桌面端永远产不出来，选项已删。

## 工程

- 自己实现的 RPC / 配置层都配了检查：`pi-rpc`（白名单 ↔ 参数表 ↔ 类实现三方对齐）、`pi-resources`（来源解析 / 安装位置 / 资源发现 / frontmatter）、`pi-entry`（三种安装布局反解入口）、`prompt-history`、`pi-update`；
- 设置页跳转抽成 `updateSettingsTab()` 纯函数，并加了一条扫描检查：源码里 `openSettingsModal('…')` 指向不存在的页面就报错；
- 打包产物里不再含 `@earendil-works`，发布检查清单加了这一条。

## 已知限制

- macOS 安装包未签名 / 未公证，首次打开需要在「系统设置 → 隐私与安全性」放行；Windows 未做代码签名，SmartScreen 可能提示未知发布者。
- Linux 的 `AppImage` 需要 `libfuse2`；没有 FUSE 的环境请用 `tar.gz`。
- 终端依赖本机已装的 CLI 与 shell，应用不会代为安装、登录或配置。
- 文本文件读取 / 保存上限 20 MB，超过 2 MB 以只读大文件模式打开。
- 「从 Git 克隆」不会代为处理凭据：需要登录的仓库请先配好凭据助手或 SSH key。

## 校验

发布产物附 `SHA256SUMS.txt`，覆盖三个平台的全部安装包。
