# Pi Desktop v0.9.1

**0.9.0 上线后反馈的几个问题集中修一遍：关软件后 Pi 进程残留、会话列表名字和 CLI 对不上、工具开关显示 0 / 8 等。**

安装包与 0.9.0 相比没有结构变化，覆盖安装即可；0.9.0 的自动更新可以直接升到这一版。

## 修复

### 关掉软件后 Pi 还挂在后台

Windows 上 `Process.Kill()` 只结束直接子进程，Pi 拉起的 MCP server、子代理会变成孤儿一直留着（父进程没了它们还在，任务管理器里能看到一串 `node`）。现在宿主给每个 Pi worker 建一个 Windows Job 对象并设置 `KILL_ON_JOB_CLOSE`：

- 停 worker 时连带结束整棵进程树；
- 宿主崩溃或被任务管理器强杀时，系统关闭 Job 句柄也会一起收掉；
- 停之前先关 stdin，给 Pi 800 ms 自己收尾（它会顺手关掉 MCP server），超时才强杀。

终端会话用同一套机制。

### 会话标题和 CLI 显示的不一致

会话名是 Pi 写进 JSONL 的一条 `session_info` 记录。桌面端以前只读文件末尾 2 MB 找它，改过名之后又追加了几十上百 MB 的长会话就再也找不到，标题退回首条消息，于是侧边栏显示「请先了解一下本项目」而 CLI 显示「Pi Desktop」。

现在记住「已扫到第几个字节」，文件只追加所以下次只看新内容；第一次碰到老文件会完整扫一遍（164 MB 约 150 ms，之后走缓存）。

### 引用会话的标题是路径原文

引用另一个会话时首条消息以 `<session name="C:\…jsonl" title="…">` 开头，列表里就显示成一长串路径。现在显示被引用会话**当前**的名字，例如 `Pi Desktop（引用）`；被引用的会话改了名也能跟上，找不到文件才退回引用时记下的标题。

### 工具开关把「没配过」当成「全关掉」

没写 `defaultTools` 时页面显示「内置工具 0 / 8」并报红，实际 Pi 用的是默认的 `read` / `bash` / `edit` / `write` 四个。现在显示 4 / 8；只有显式写了 `[]` 才是 0 / 8，并提示可以恢复默认。每项后面的徽标由「默认启用」改成「Pi 默认」，不再和开关状态自相矛盾。

### 不记住上次打开的项目

`recent-workspaces.json` 里永远是空数组，关掉再开要重新选目录。

### 升级后仍提示「有更新」

更新检查复用了缓存里旧版本算出的 `updateAvailable`，升级到 0.9.0 后仍弹「有更新 0.9.0」。现在每次都按当前版本重算。

### 模型 / 思考菜单被活动头压住

菜单改用 `marginLeft` 平移定位，不再用 `transform`（那会创建层叠上下文，被 z-index 更高的活动头盖住）。

## 新增

- 设置 → 扩展 → 工具开关：**「恢复 Pi 默认」**按钮，直接删掉这一作用域的 `defaultTools` 键（Pi 缺省就是四个内置工具）。注意：写成空数组表示「一个都不启用」，和删掉不是一回事。

## 已知限制

- Windows 依赖系统 WebView2（Windows 11 自带；Windows 10 若缺失需安装 Evergreen Runtime）。
- macOS 安装包未签名 / 未公证，首次打开需要在「系统设置 → 隐私与安全性」允许；Windows 未做代码签名，SmartScreen 可能提示未知发布者。
- Linux 使用 `tar.gz` 内的 `install.sh` 安装到 `~/.local`，或使用 `deb` / `rpm`；桌面环境需要 WebKitGTK 4.1。
- 终端依赖本机已安装的 CLI 与 shell，应用不会代为安装、登录或配置。
- 文本文件读取 / 保存上限 20 MB，超过 2 MB 以只读大文件模式打开。

## 校验

- 下载 `SHA256SUMS.txt`，与本地文件比对：`sha256sum -c SHA256SUMS.txt`（Windows 可用 `certutil -hashfile <文件> SHA256` 手工对照）。
- 从 0.9.0 升级：设置 → 关于 → 检查更新，应能直接下到本版并自动重启。
- 升级后关闭软件，任务管理器里不应残留 `node`（Pi）、`linkup-mcp-server` 一类子进程。
