# Pi Desktop v0.9.4

修的是「装完第一眼」：初始窗口不再一开就贴满屏幕，并且按任意分辨率、缩放与多显示器自动适配。

## 问题

初始窗口尺寸以前写死 `1400×900`（DIP）。这台机器是 1920×1080 开 125% 缩放，逻辑工作区只有 **1536×864**：

- 宽度 1400 < 1536，放得下
- 高度 900 > 864，**放不下** → 被系统压到满屏高度
- 压完的结果连同 `y = -18` 一起写进 `%APPDATA%\Pi Desktop\window-state.json`

于是之后每次启动都恢复成「贴满屏幕 + 标题栏顶到屏幕上沿」，看起来像被最大化过，实际上只是默认尺寸没考虑缩放后的工作区。

## 现在的行为

- **首次启动按工作区给尺寸**：取 `1400×900` 与「当前主显示器工作区 × 86%」的较小值。上面那台机器得到 **1320×743**，四周留出正常边距。
- **旧状态不再沿用**：窗口状态的 key 换成 `main-v2`，升级后第一次打开就是新尺寸，不需要手动删 json。
- **恢复状态后兜底**：窗口如果跑出工作区，会被拉回来并缩进可见范围（以前只会丢失位置，尺寸超界照样撑出去）。
- **极小屏 / 高缩放**：最小尺寸 `980×640` 在工作区更小时跟着缩小，竖屏、4K 高缩放、小笔记本都不会撑出屏幕。
- **多显示器**：兜底改为匹配**窗口所在的那台显示器**（以前固定按主显示器算，副屏上的窗口会被拽回主屏）。
- **分辨率 / 缩放热切换**：监听显示器变化，插拔外接屏或改分辨率后，非最大化窗口会自动收回当前工作区。

## 校验

- `npm run check`：57 个界面 / 纯逻辑检查 + 3 个静态分析全部通过。
- `go vet ./...` 与 `go test ./...` 通过。
- 真机实测（工作区 1536×864）：窗口 `1320x743`，居中，标题栏完整可见。
- 用越界状态 `(-500,-400) 1700×1100` 验证兜底：启动后窗口收回屏幕内，标题栏可见。

## 已知限制

- 安装包仍未签名，macOS 首次打开需要在「隐私与安全性」里放行。
- 大会话（100 MB 以上）首次打开可能超过 25 秒的启动超时，之后单独处理。
