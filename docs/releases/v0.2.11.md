# Pi Desktop v0.2.11

修 `/resume`、`/compact` 后面那个参数提示的显示问题：错位、贴字、盖到附件上。

## 问题

`/` 命令打完后，输入框里会用灰色文字提示参数（`<会话>`、`[压缩要求]`）。这个提示是画在输入框上面的一层透明副本，之前有两处没对齐：

- **横向错位 4px、纵向偏上 4px**：提示层写的是 `top: 9px; left: 10px`，输入框自己的内边距是 `13px 14px`。
- **字体不一样**：`<textarea>` 不继承字体，落回浏览器默认等宽字体，而提示层用的是界面字体。同一个字符串两边宽度不同，提示自然对不齐，看着像 `/resume<会话>` 挤在一起。
- **有附件时直接盖住附件**：提示层挂在 `.composer-field` 上，而附件条（`@` 引用的对话、图片）是插在输入框上方的；一加附件输入框就下移，提示层还钉在顶部，结果画到了附件卡片上。

## 修复

- 提示层挪进**只包输入框**的新容器 `.composer-input`，附件条再怎么插都影响不到它。
- 对齐改成与输入框内边距完全一致的 `13px / 14px`，并显式指定同款字体与行高 —— 提示现在紧贴光标、和正文同一基线。
- 输入框改为继承界面字体（`font-family: inherit`），正文与提示宽度一致；这也让输入的文字和界面其余部分统一，不再是浏览器默认等宽。
- 多行内容不显示这条提示（没法对齐于某一行），命令菜单打开时也不显示。

## 校验

新增 `arg-hint.electron.mjs`（已接入冒烟）：

- `/compact `、`/resume ` 两种命令：提示内容分别是 `[压缩要求]`、`<会话>`；提示层相对输入框内容区偏移 **dx = 0、dy = 0**；透明副本宽度与输入框字体测得的宽度一致（65.44px = 65.44px）
- 提示层不能直接挂在 `.composer-field` 上，附件条必须在它的容器之外
- 真插一个附件条进 DOM：输入框下移后提示仍贴合正文（dy = 0）且没有跑出输入框
- **反向验证**：把内边距改回旧的 `9px / 10px` 重新构建，检查立刻失败并报 `实际差 -4px`

`npm run check` 全绿，Electron 冒烟 12 步全 PASS。
