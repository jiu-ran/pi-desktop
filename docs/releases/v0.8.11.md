# Pi Desktop v0.8.11

两处「别再自相矛盾」的修正：检查更新不再白白消耗 GitHub 配额，重连成功后不再挂着「请检查网络」。

## 检查更新：少发请求，也别把话说得像是软件的错

先说结论：被限流**不是你的使用次数高**。GitHub 匿名接口的 60 次/小时是按**出口 IP** 算的，
走代理时那是代理节点的 IP，上面还有别人在打 GitHub API —— 撞上被占满的节点就会报错。
本机实测同一个代理连查 `/rate_limit`，会交替拿到「已用 60/60」和「已用 11/60」两种结果。

不过原来的实现确实在浪费，一并改掉：

- **缓存落盘**：最近一次成功结果、ETag、限流恢复时间都写进 `<用户数据>/app-update-cache.json`。
  以前只在内存里，重启应用就等于再发一次请求；现在 6 小时内跨启动复用，版本号变了自动失效。
- **条件请求**：检查更新会带 `If-None-Match`（ETag）。GitHub 规定 **304 不消耗配额**，
  所以「内容没变」的检查现在是 0 配额。
- **限流期间不发请求**：恢复时间之前只回一句「约 21:27 恢复」，重启应用也一样。
- **提示说清口径**：`服务器限制请求频率（GitHub 匿名接口每小时 60 次，按出口 IP 计算；走代理时与其他用户共用），约 21:27 恢复`。

## 重连成功后不再挂「检查网络或代理后再发一次」

断网时那条卡片会给一步建议，重连成功后标题变成「已重新连接（第 N 次重试）」，但副标题
被留了下来 —— 于是出现「已经连上了，还让你去检查网络」这种自相矛盾的话。

现在：只要重连成功，副标题就收掉；只有**重试彻底失败**时才保留这句建议。
