# Pi Desktop v0.9.7

这一版主要解决「明明装了 pi，桌面端却认不出来」：官方安装器的 `pi.cmd → pi-launcher.js` 布局、PATH 里看不到、新版 npm 包的 `dist/bundle/cli.js`，现在都能正确解析并拉起会话。顺带把「进程出错」的原因摆到台面上，再打磨了两处界面细节。

## Pi 的识别

之前只认两件事：PATH 上有 `pi`，以及 npm 布局的 `node_modules/…/dist/cli.js`。于是出现了两种「设置里正常、工作区红点」的情况：

- **官方安装器**（`pi.dev` 的安装脚本）把真正入口放在 `<agentDir>\bin\pi-launcher.js`，`pi.cmd` 只是转发；桌面端找不到 `dist/cli.js` 就报错。
- **PATH 里没有**：Windows 的 PATH 是登录时继承的，装完 pi 不注销，已在运行的桌面端就看不见它。

现在按这个顺序认：

1. 设置里的**手动路径**（`.cmd`、可执行文件、`.js` 都可以，`.js` 会用 node 拉起）
2. **PATH** 上的 `pi` / `pi.cmd` / `pi.exe`
3. PATH 没有时，扫**已知安装目录**并逐个 `pi --version` 探活：
   `<agentDir>/bin`（官方安装器）、`%APPDATA%\npm`、`%LOCALAPPDATA%\pnpm`、`%LOCALAPPDATA%\Programs\pi`、`~/.bun/bin`、`~/.local/bin`、`~/bin`、`~/.bin`、`~/.nix-profile/bin`、`/opt/homebrew/bin`、`/usr/local/bin`

认出来之后按来源决定启动命令：

| 安装方式 | 入口 | 怎么起 |
|---|---|---|
| 官方安装器（Windows） | `<agentDir>\bin\pi.cmd` → `pi-launcher.js` | `node …\pi-launcher.js --mode rpc`（launcher 自己读 `install/current-version`、设 `PI_MANAGED_INSTALL_ROOT`） |
| 官方安装器（macOS / Linux） | `<agentDir>/bin/pi`（sh launcher），常以 `~/.local/bin/pi` 软链暴露 | 直接执行 launcher（它自己把随包 Node 放进 PATH） |
| npm / pnpm 全局 | `<prefix>/pi.cmd`（Windows）、`<prefix>/bin/pi`（Unix） | 解析 shim 里的入口后 `node …/dist/cli.js`（老包）或 `…/dist/bundle/cli.js`（新包） |
| bun 全局 | `~/.bun/bin/pi` | 能解析相对入口就用 node，解析不到就直接执行（shebang 指向 bun） |
| Nix | `~/.nix-profile/bin/pi` 包装脚本 | 直接执行 |
| 源码 / 自定义 | 手动填 `dist/cli.js` 或 `pi-launcher.js` | `node <该 js> --mode rpc` |

设置 → Pi CLI 的路径后面会标出来源（PATH / 官方安装器 / npm 全局 / 手动指定），`pi.log` 里的「Pi 启动命令」也记来源与实际路径 —— 「哪个 pi 在跑」不用猜。

## 「进程出错」不再是个哑巴

以前标题栏只有红点和「进程出错」四个字，原因藏在侧栏项目行的悬停提示里，`pi.log` 里什么都没有。

现在：

- 标题栏状态胶囊在「进程出错」时，**悬停直接显示错误原文**
- `pi.log` 记录 **Pi 启动命令 + 来源 + 路径**；解析失败也落一条日志
- 找不到 pi 时的报错会列出已经查过哪些来源，并指向 <https://pi.dev>

## 界面

- **项目名后的会话数**：改成 10.5px 等宽数字的圆角小徽标（原来是无背景的灰数字，紧贴项目名读起来像标题的一部分）；`99+` 自动撑开，深色主题跟随 token。
- **输入框右下控件对齐**：会话用量、发送方式、停止、发送统一 26px 高、7px 圆角、6px 间距；上下文占比原来 50% 就变橙，改成 70% 提示、90% 告警，低占比用中性色，百分比定宽（`9% → 100%` 时右侧按钮不抖），0% 不再画出一个圆点；「停止」去掉红色描边只留淡红底，不再和「发送」抢视线；四个控件补上键盘焦点描边。

```bash
npx mygo build

```

另外补了一组安装布局的回归测试（`internal/host/entry_test.go`，8 个用例）：官方安装器 shim、launcher 优先、npm 布局、bundle 入口、相对路径、未知 shim、直填 `.js`、PATH 缺失时回退安装器目录。

## 仍存在的限制

- Windows 依赖系统 WebView2（Windows 11 自带；Windows 10 缺失时需装 Evergreen Runtime）。
- macOS 安装包未签名 / 未公证；Windows 未做代码签名，SmartScreen 可能提示未知发布者。
- 终端依赖本机已安装的 CLI 与 shell，应用不会代为安装或登录。
- 识别安装方式依赖 Pi 的磁盘约定（`<agentDir>/bin`、各包管理器全局目录）。Pi 若改布局，这里要跟着改；识别不出时可在「设置 → Pi CLI」手动指定 `.js` 入口。
