# Pi Desktop v0.2.5

这一版把「对话」变成可以引用、可以改写的东西（`@` 引用对话、编辑排队消息），把运行日志搬进项目目录，按「Pi 自带的留核心、其余做成插件」重画了能力边界，设置界面也重做了一遍。

### 新增

- **用 `@` 引用对话**：输入框里打 `@`，选择器多出「引用对话」一组，列出本项目的其它会话（排除当前会话），可按标题搜索。选中后变成一枚「对话」附件（显示名称与消息条数，可随时移除），发送时把那个会话压成一段上下文块放进提示词：只取用户与助手的文字，头部几条加最新若干条、中间省略并注明省略条数，单条 700 字、整块 12k 字封顶；工具结果与内联附件正文不进上下文。实测 85MB / 1.2 万条的会话引用一次约 1.2 万字符（首次 326ms，之后走增量缓存 3ms）。
- **引用其它项目的对话**：`@` 里还能跨项目引用——每个项目列最近几个会话，带「刚刚 / N 分钟前」提示，搜索按标题匹配。这是桌面端能力，做成可停用的 `session-quote` 插件；停用后 `@` 只剩 Pi 自带的文件补全。
- **编辑引用的对话**：点输入框里的「对话」附件打开编辑框，可以改显示名称，也可以直接改写要注入的正文（默认是自动摘要）。改过的引用带「已编辑」标记，发送时用你的正文；「恢复自动摘要」一键还原。编辑框里只显示正文，外层 `<session>` 包裹由发送时重新拼，不会套娃。
- **编辑排队中的消息**：待发送的消息（对话里的「待发送」气泡、或输入框上方的待发送卡片）现在可以直接改写：Enter 保存、Esc 取消。保存时清空队列并按原顺序重新入队（Pi 只能整体清空），只替换这条的消息文字，自动附带的文件 / 引用上下文原样保留；重新入队失败会把内容放回输入框，不会把排队的话弄丢。
- **运行日志**：写在当前项目下的 `.pi-desktop/logs/`（自动加入该仓库的 `.git/info/exclude`，不会出现在改动里、也不会出现在文件树与 `@` 补全中），分 `app` / `renderer` / `pi` / `perf` 四个文件，记录启动退出、IPC 失败与慢调用、前端报错、会话与压缩事件、卡顿。单文件 8MB 轮转、总量硬上限 100MB、从最旧删起，正在写的文件永不删；写入前脱敏（token、`Bearer`、`api_key=`、超长 base64）。设置 → 运行日志可看占用、打开目录、一键清理。
- **能力归属明确**：按「Pi 自己有没有这个能力」划分——对话与内置工具卡片、会话、`@` 文件引用、斜杠命令、模型与思考等级、Skills / MCP / Packages / AGENTS.md 留在核心且不可停用；子代理、Mermaid、引用对话、项目文件树、版本控制、终端、RPC 事件都做成插件。核心不再直接 import 插件组件，只认插件注册的工具渲染与 `@` 来源。

### 修复

- **排队消息在界面上出现两次**：流式期间发出去的消息会先乐观渲染成气泡（否则引导消息要等重开会话才看得见），而 Pi 的队列里同一句还在，于是输入框上方又列一遍「待发送」。现在气泡是唯一表现形式：队列里能对上气泡的条目不再重复列出（按实际发出的完整提示词匹配，附件也算在内），对不上的才显示成待发送卡片。
- **撤回排队消息后气泡还在**：撤回只清空了队列，界面上那条却留着，看起来像已经发出去。现在撤回会删掉对应气泡，并把文字放回输入框（附件块换成可读标签，不会把 XML 塞回去）。
- **编辑带附件 / 引用的排队消息会丢掉上下文**：以前按「提示词末尾是否等于消息文字」判断，带文件或引用时末尾对不上就整段替换。现在按最后一个 `</file>` / `</directory>` / `</session>` 切开，上下文永远保留，只替换后面那段用户文字。
- **损坏的会话文件会把整个工作区搞失灵**：会话文件被改坏（或不是 Pi 的格式）时，切换报「Session file is not a valid pi session」，worker 停在半切换状态，之后每个操作都变成「这个工作区还没有启动 Pi」。现在启动时跳过坏会话、切换时丢掉那一槽 worker 并给可操作提示（文件保留），工作区照常可用。
- **移除最近项目后满屏「项目目录尚未获得授权」**：从最近项目移除时主进程撤销了该目录授权，界面却还留着这个工作区，之后每次会话刷新都失败，多个调用路径各弹一张提示。现在移除会一并清掉本地工作区并切到剩余项目。
- **后台清理动作在打包版里没有出口**：清理旧安装包原本只写 stdout，打包版没有终端就看不到。现在写进项目日志。

### 改进

- **设置界面重做**：左侧导航按「对话与 Agent / 界面 / 桌面端」分组并显示图标，支持搜索过滤；右侧增加分区标题与说明，配置项改成卡片分组、细线分行、右侧控件统一宽度；底部精简为「恢复默认 / 完成」并提示改动会立即保存。窗口变窄时导航折行、行布局改为上下排列。
- **待发送的展示重做**：原来是一行灰色小胶囊、内容直接铺原始提示词（带 `<file name="…">` 这种 XML）。现在排队中的消息在对话里带「待发送」标记（呼吸点 + 弱化气泡），输入框上方只列还没进对话的条目：模式标签（排队 / 插话）、单行截断预览、附件换成 `[文件: 路径]`、右侧「撤回」，并显示条数。
- **卡顿日志能说清是哪一侧慢**：除了主进程阻塞，现在还会记录超过 400ms 的 IPC 调用（哪个通道、鉴权还是执行耗时）与超过 1 秒的渲染进程长任务；再遇到「界面卡死」可以直接看出是主进程还是渲染进程、卡多久、卡在哪个调用上。
- **重复提示合并**：同一条消息短时间重复出现时合成一张卡片（显示 ×N）并重置消失计时，不再堆三四张一模一样的。
- **坏会话不再污染其它会话**：侧栏会跳过损坏的会话文件，选中时提示可操作原因，而不是让整个项目变成「未启动」。

### 技术细节

- `electron/session-context.ts`：会话摘要只取 `user` / `assistant` 的文字块，头 2 条 + 最新若干条，单条 700 字、整块 12k 字，输出 `<session name title messages>` XML 块（转义），与渲染侧 `buildSessionBlock` 保持同一格式（有回归用例钉住一致性）。
- `packages/ui/src/shared/queue-view.ts`：`planQueueView` 按完整提示词匹配气泡、`splitPromptMessage` 拆分上下文与用户文字、`replacePromptMessage` 只替换尾巴；Pi 的队列 API 只有 `prompt` / `steer` / `followUp` / `abort` / `clearQueue`，没有「删一条」，所以编辑走「清空 → 按序重新入队 → 替换目标」。
- `packages/ui/src/shared/session-block.ts`：`buildSessionBlock` / `extractSessionBody` 负责外层包裹的拆与拼，编辑只面对正文。
- `electron/logger.ts`：四个日志流共用一套内存缓冲（400ms flush），每次 flush 前 `stat` 真实大小，超量按时间删最旧；`useProjectLogs(cwd)` 切换目录前先 flush，未选项目时先攒内存（256KB 上限）再补写。
- `packages/ui/src/kernel/plugin-manager.ts`：新增 `registerMentionSource` 与 `registerToolRenderer` 两个注册表，插件停用自动注销；核心组件只查注册表，不引用插件目录。
- `scripts/checks/capability-boundary.check.ts`：把「能力归属表」变成测试——插件清单与文档表格不一致、核心里出现对话引用实现、核心 import 插件组件，都会失败。
- `scripts/checks/settings.electron.mjs`：设置界面的几何与行为回归（分组、图标、唯一高亮、标题与说明、10 个分区逐个检查横向溢出、搜索过滤、底部按钮）。
