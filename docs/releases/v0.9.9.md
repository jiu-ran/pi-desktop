# Pi Desktop v0.9.9

这一版只修一个「会话凭空少了一条」的问题。

## 症状

项目里明明有 5 条会话，`pi` 命令行里 `/resume` 也看得到 5 条，桌面端侧栏只列 4 条，项目名后面的数字也是 4。

## 原因

桌面端为了排序和显示标题，会读每个会话文件的**开头**做摘要（不读整份，避免打开项目时把所有历史都扫一遍）。这个窗口原来是 **128 KB**。

出问题的那条会话，首条用户消息是一整行带图片 base64 的 JSON —— 实测 **137,586 字节**，超过窗口。这一行被截断后不再是合法 JSON：

1. `json.Unmarshal` 失败 → 跳过这一行
2. 找不到首条用户消息 → 标题为空、`Empty = true`
3. 侧栏列表把 `Empty` 会话过滤掉（这个过滤原本是为了隐藏「刚点新建、还没说话」的空会话）

所以会话并没有丢，文件一直在磁盘上，只是没被列出来。`pi` CLI 直接读整行，所以它显示正常。

## 改法

- 摘要读取窗口 **128 KB → 512 KB**（`sessionHeadLimit`），覆盖绝大多数带内联图片的首条消息；
- `readHeadText` 额外返回「是否被截断」；
- 新增 `titleFromPartialUserLine`：只有当**最后一行**被截断、且这一行确实是一条消息时才走容错提取 ——
  - 先取 `text` 块，`<file name="…"></file>` 这类附件标记照常剥掉，标题取正文；
  - 没有文字只有图片时退成「图片消息」；
  - `role` 字段被长图片挤到截断点之后时，只要没有明确的 `assistant` 标记也按用户消息处理；
- 正常（未截断的）文件走的还是原来的解析路径，行为不变。

## 校验

```bash
npm run check                # 61 项前端检查 + go test ./...（46 个 Go 测试）
npm audit && npm audit --prefix packages/ui
npx mygo build
PI_DESKTOP_SMOKE=1 PI_DESKTOP_SMOKE_PTY=1 PI_DESKTOP_SMOKE_BASH=1 \
PI_DESKTOP_SMOKE_PROMPT=1 PI_DESKTOP_SMOKE_UI=1 PI_DESKTOP_SMOKE_SETTINGS=1 \
PI_DESKTOP_SMOKE_REPO=1 npx mygo dev
```

新增 4 条回归测试（`internal/host/session-title_test.go`）：截断后仍能取到正文、纯图片退成「图片消息」、assistant 的截断消息不误判、700 KB 首条消息的端到端摘要。另外对真实会话目录跑了一次 `listSessions`：**4 条 → 5 条**，补回的那条标题是「我想要使用这个同步」。

## 仍存在的限制

- 若某条会话的首条消息文本本身超过 512 KB（例如一张超大截图后面才写字），标题仍会退成「图片消息」而不是正文 —— 会话会正常显示，只是标题不够精确。
- 其余限制与上一版一致：Windows 依赖系统 WebView2；macOS 安装包未签名 / 未公证，Windows 未做代码签名；终端依赖本机已安装的 CLI。
