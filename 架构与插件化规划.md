## 1. 双层扩展边界（核心原则）

Pi CLI 本身已具备完整的 Agent 扩展能力（Tools / Skills / Prompts / Extensions / MCP）。Pi Desktop 的插件体系**只负责桌面端视图与交互扩展**，严格遵循“单一真相源”原则：

```mermaid
flowchart TB
    subgraph Desktop["Pi Desktop 桌面客户端（只管视图、面板与交互）"]
        direction TB
        UIShell["UI Shell 工作台骨架 (Vue 3)"]
        PluginKernel["Plugin Kernel 插件内核 (Registry + Context)"]
        
        subgraph BuiltinPlugins["内置与扩展 UI 插件"]
            P1["tool-cards\n工具专属卡片插件"]
            P2["side-panels\n变更 / 终端 / 会话树面板"]
            P3["composer-addons\n/ 斜杠命令 / 队列切换 / 附件"]
            P4["extension-dialogs\n扩展弹窗与状态栏桥接"]
            P5["themes\n浅色 / 深色 / 代码高亮主题"]
        end

        CoreStore["Core 核心模块\nWorkspacePool · SessionIndex · TranscriptStore"]
        HostBridge["HostBridge 跨壳通信契约 (Electron / Tauri 2)"]

        UIShell --> PluginKernel
        PluginKernel --> BuiltinPlugins
        UIShell --> CoreStore
        PluginKernel --> CoreStore
        CoreStore --> HostBridge
    end

    subgraph LocalPi["用户本机 Pi CLI（唯一 Agent 真相源）"]
        direction TB
        RpcClient["官方 RpcClient (stdin / stdout JSON Lines)"]
        PiProcess["pi --mode rpc (每工作区独立子进程)"]
        PiConfig["~/.pi/agent 与项目 .pi/\nmodels · auth · settings · skills · extensions · mcp · sessions"]

        RpcClient <--> PiProcess
        PiProcess <--> PiConfig
    end

    HostBridge <-->|"IPC 双向事件与命令"| RpcClient
```

## 4. 消息与插件事件流转时序

```mermaid
sequenceDiagram
    autonumber
    actor User as 用户
    participant UI as Workbench / Composer
    participant Store as TranscriptStore (Core)
    participant Reg as PluginRegistry
    participant Host as Electron Main (RpcClient)
    participant Pi as 本机 pi --mode rpc

    User->>UI: 输入消息并发送 (Enter)
    UI->>Store: send(cwd, text)
    Store->>Host: ipc.prompt(cwd, text, streamingBehavior)
    Host->>Pi: {"type": "prompt", "message": "..."}
    Pi-->>Host: {"type": "response", "command": "prompt", "success": true}

    loop 流式输出与工具调用
        Pi-->>Host: message_update (thinking_delta / text_delta)
        Host-->>Store: pi:event
        Store-->>UI: 增量更新气泡 (markstream-vue 渲染)

        Pi-->>Host: tool_execution_start (toolName, args)
        Host-->>Store: pi:event
        Store->>Reg: resolveToolRenderer(toolName)
        Reg-->>UI: 挂载对应插件卡片 (BashCard / EditDiffCard / McpCard)

        opt 本机 Pi 扩展请求交互弹窗
            Pi-->>Host: extension_ui_request (select / confirm / input)
            Host-->>Reg: 分发给 extension-dialogs 插件
            Reg-->>User: 弹出原生对话框
            User->>Reg: 确认选择
            Reg->>Host: extension_ui_response (id, value)
            Host->>Pi: 写回 stdin
        end
    end

    Pi-->>Host: agent_settled
    Host-->>Store: 标记运行结束 (running = false)
```

## 5. 五大插件贡献点清单

| 贡献点标识 | 挂载位置 | 典型内置插件 | 核心能力说明 |
| :--- | :--- | :--- | :--- |
| `toolRenderers` | 消息流工具卡片区 | `bash-card`、`edit-diff-card`、`read-card`、`mcp-card` | 根据 `toolName` 匹配专属折叠摘要与展开详情组件 |
| `sidePanels` | 顶栏按钮 + 右侧抽屉 | `panel-changes`、`panel-terminal`、`panel-session-tree` | 动态注册右侧工具面板与顶栏开关徽章 |
| `composerAddons` | 输入框上方工具条 | `slash-commands`、`queue-manager`、`image-attachment` | 调用 `get_commands` 补全技能与 `/` 命令、管理 `followUp`/`steer` |
| `extensionUiHandlers` | 全局模态框 / 状态栏 / Widget | `extension-dialogs`、`extension-statusbar` | 完整实现 `rpc-extension-ui.md` 协议 |
| `themes` | 根节点 CSS 变量 + 代码块 | `theme-dark`、`theme-light` | 统一驱动界面 CSS 变量与 `markstream-vue` 的 Shiki 主题 |

## 6. 四阶段重构与落地路线

- **Phase 1：Core 与 HostBridge 抽离（模块化地基）**
  - 从 `App.vue` 抽离 `core/transcript-store.js` 与 `core/host-bridge.js`。
  - 保持现有全部功能可用，消除 `App.vue` 中的协议拼接细节。
- **Phase 2：PluginRegistry 与面板/主题插件化**
  - 建立 `plugins/registry.js`，将“变更面板”、“终端面板”、“深浅色主题”迁移为首批标准插件。
- **Phase 3：工具调用卡片插件化（视觉体验升级）**
  - 实现 `bash`（命令+退出状态+终端输出）、`edit`/`write`（文件路径+变更对比）、`read`（文件预览）、`mcp__*`（服务名+参数表）四类专属卡片插件。
- **Phase 4：Pi 原生扩展 UI 桥接与斜杠命令**
  - 落地 `extension-dialogs` 插件（支持 `select` / `confirm` / `input`）与 `slash-commands` 插件（支持 `/` 唤起本机 Skills 与命令）。
